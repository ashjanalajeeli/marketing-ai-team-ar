# فريق التسويق الذكي

تطبيق ويب عربي باتجاه RTL يحوّل بيانات المشروع إلى حزمة تسويقية عملية، عبر تنسيق ستة أدوار تسويقية متخصصة ثم تجميع مخرجاتها في خطة واحدة.

## الميزات

- إدخال اسم المشروع وفكرته والجمهور والبلد والمدة والميزانية والقطاع والأهداف.
- تشغيل ستة أدوار: مدير التسويق، الاستراتيجي، باحث الجمهور، مخطط المحتوى، الكاتب الإعلاني، وكاتب السيناريو.
- إنشاء ملخص تنفيذي واستراتيجية تموضع ورسالة وقيم ونبرة وقنوات.
- إعداد خطط سنوية وشهرية وأسبوعية وخطة تنفيذ، وتقويم محتوى، ونماذج إعلانية، وسيناريوهات فيديو.
- حفظ المشاريع والمخرجات وحالة التشغيل في MySQL، وإعادة تشغيل الوكيل وتحرير المخرجات ونسخها.
- حفظ مسودة النموذج محليًا في المتصفح، مع تسجيل دخول OAuth لحفظ المشاريع.

## المتطلبات

- Node.js 20 أو أحدث.
- pnpm؛ يحدد `package.json` الإصدار 10.4.1.
- قاعدة بيانات MySQL متاحة.
- إعداد OAuth متوافق مع مسارات التطبيق.
- نقطة نهاية متوافقة مع واجهة Chat Completions ومفتاح وصول لتوليد المخرجات.

## التشغيل محليًا

```bash
pnpm install --frozen-lockfile
cp .env.example .env
```

املأ المتغيرات المطلوبة في `.env` محليًا، ثم أنشئ/حدّث مخطط قاعدة البيانات وشغّل التطبيق:

```bash
pnpm db:push
pnpm dev
```

يبدأ الخادم افتراضيًا على المنفذ `3000`، أو على قيمة `PORT`، ويختار منفذًا قريبًا إذا كان المنفذ مشغولًا.

## البناء والتحقق

```bash
pnpm check
pnpm test
pnpm build
pnpm start
```

يُنتج `pnpm build` ملفات الواجهة في `dist/public` والخادم في `dist`، ويشغّل `pnpm start` نسخة الإنتاج.

## متغيرات البيئة

يسرد `.env.example` أسماء المتغيرات فقط ويترك قيمها فارغة. لا تضع أي مفاتيح أو كلمات مرور في Git.

| المتغير | الاستخدام |
| --- | --- |
| `VITE_APP_ID` | معرّف التطبيق العام المستخدم في بدء OAuth. |
| `VITE_OAUTH_PORTAL_URL` | عنوان بوابة تسجيل الدخول التي يستخدمها المتصفح. |
| `OAUTH_SERVER_URL` | عنوان خدمة OAuth الخلفية. |
| `JWT_SECRET` | سر توقيع جلسات المستخدم؛ يجب أن يبقى على الخادم. |
| `DATABASE_URL` | عنوان اتصال MySQL؛ مطلوب لحفظ المشاريع والمخرجات. |
| `OWNER_OPEN_ID` | اختياري؛ يحدد هوية المالك لمنح دور الإدارة. |
| `BUILT_IN_FORGE_API_URL` | عنوان واجهة النموذج/التخزين المتوافقة؛ يستخدم الكود عنوان Forge الافتراضي للنموذج عند تركه فارغًا، بينما يتطلب وسيط التخزين عنوانًا مضبوطًا. |
| `BUILT_IN_FORGE_API_KEY` | مفتاح الواجهة الخلفية لتوليد النص والوصول إلى وسيط التخزين. لا يُضمّن في الواجهة. |
| `PORT` | منفذ الخادم؛ الافتراضي `3000`. |
| `VITE_ANALYTICS_ENDPOINT` | عنوان نقطة Umami الاختيارية المشار إليها في HTML. |
| `VITE_ANALYTICS_WEBSITE_ID` | معرّف الموقع لدى نقطة التحليلات الاختيارية. |

أي متغير يبدأ بـ`VITE_` يُضمّن في حزمة المتصفح؛ استخدمه فقط لقيم عامة، ولا تضع فيه أسرارًا.

## ملاحظة حول التكلفة والخدمات

لم تُضف إلى هذا المستودع أي خدمة مدفوعة أو موفر خارجي جديد. يحتفظ المصدر بتكامل النموذج الموجود أصلًا، ويحتاج إلى مفتاح لنقطة متوافقة؛ قد تكون الاستضافة أو طلبات النموذج خاضعة لحدود أو رسوم الجهة التي توفر المفتاح. المستودع لا يحتوي على مفاتيح أو رصيد خدمة، ولا يضمن مجانية الاستخدام لدى مزود خارجي. لتجنّب أي تكلفة، استخدم نقطة متوافقة تملك لها حصة مجانية مؤكدة أو استضافة محلية، ولا تُفعّل التحليلات إلا إذا أردتها.

## بنية تقنية مختصرة

- الواجهة: React وTypeScript وVite وTailwind CSS، مع دعم RTL.
- الخادم: Express وtRPC.
- التخزين: Drizzle ORM مع MySQL.
- التحقق من أنواع TypeScript: `pnpm check`.
